# Terminal Portal Documentation

User guides for the Sindo Ferry portals, built with [Docusaurus](https://docusaurus.io/).

- **Source** lives on the `main` branch of this repo.
- **Published site** is built by CI and pushed to the `gh-pages` branch, which
  GitHub Pages serves at **https://sindo-ferry.github.io/ts-documentation/**.

> This repo is **public**. Anything committed here — including pages marked
> `draft: true`, which are excluded from the built site but still readable in
> source — is world-visible. Keep unpublished or internal material out of it.

## Structure

```
├── docs/
│   ├── intro.md                       # Overview / landing page (slug: /)
│   ├── register-account.mdx           # Shared: sign up, confirmation, activation
│   ├── how-it-fits-together.mdx       # Entity/setup dependency map (currently draft)
│   ├── public-live-tv.mdx             # Public departure boards
│   ├── terminal-staff/                # Terminal Portal (ts-terminal.sindoferry.com.sg)
│   │   ├── _category_.json            #   category label + order
│   │   ├── sign-in.mdx
│   │   ├── set-port-context.mdx
│   │   ├── administrative/            #   master data, schedule, trips
│   │   └── operational/               #   day-of-departure: scans, boarding, manifest
│   └── ferry-operator/                # Operator Portal (ts-operator.sindoferry.com.sg)
├── static/img/<audience>/<module>/    # screenshots, one folder per guide
├── docusaurus.config.js               # site config (url/baseUrl, nav, footer, mermaid)
├── sidebars.js                        # autogenerated sidebar (reads the docs/ tree)
└── build/                             # generated output (gitignored)
```

Guides in `administrative/` and `operational/` carry a `slug:` in their frontmatter
so their URLs stay flat (`/terminal-staff/<name>`) regardless of the subfolder.

## Local development

```bash
npm install        # first time only
npm start          # dev server → http://localhost:3000/ts-documentation/
```

Build and preview the production output:

```bash
npm run build
npm run serve      # serves ./build at http://localhost:3000/ts-documentation/
```

> Requires Node 18+.

## Adding a new guide

1. **Capture screenshots** from the running app and save them under
   `static/img/<audience>/<your-guide-slug>/` (e.g. `01-...png`, `02-...png`).
2. **Create the guide** at `docs/<audience>/<your-guide-slug>.mdx` with frontmatter:
   ```md
   ---
   id: <unique-id>
   title: <Full Title>
   sidebar_label: <Short Sidebar Label>
   sidebar_position: <N>          # order within the category
   slug: /terminal-staff/<name>   # only needed inside administrative/ or operational/
   description: <one-liner>
   ---
   ```
   Reference images with root-absolute paths, e.g.
   `![alt](/img/<audience>/<slug>/01-....png)` — Docusaurus applies the baseUrl and
   fingerprints them automatically.
3. **Link it** from `docs/intro.md` and cross-link related guides.
4. **Verify:** `npm run build`.

> **Check images by eye.** Absolute `/img/...` paths are unvalidated static assets,
> so a missing or wrong screenshot is **not** a build error. The build warns on
> broken *links*, but it will not catch a broken *image*.

Diagrams are written as ```` ```mermaid ```` fences (the `@docusaurus/theme-mermaid`
theme is enabled).

## Translations (Bahasa Indonesia)

English is the source. The Indonesian site is served at `/ts-documentation/id/`, and
readers switch with the language dropdown in the navbar.

**Any page without a translation falls back to English**, so adding a new English
guide never breaks the Indonesian site — it just shows up in English there until
translated.

| What | Where |
| --- | --- |
| A translated page | `i18n/id/docusaurus-plugin-content-docs/current/` — same relative path and filename as under `docs/`. Keep the frontmatter `id` and `slug` identical; translate `title`, `sidebar_label`, `description` and the body. |
| Sidebar section names and their index-page descriptions | `i18n/id/docusaurus-plugin-content-docs/current.json` |
| Navbar and footer labels | `i18n/id/docusaurus-theme-classic/navbar.json`, `footer.json` |
| Docusaurus's own UI text ("Next", "On this page", …) | `i18n/id/code.json` |

**Convention — what stays in English.** Anything a reader must match against the
portal screen is left untranslated, to avoid misunderstanding:

- **Menu names**, exactly as the portal's sidebar shows them — **Operators**,
  **Vessels**, **Ports**, **Gates**, **Berths**, **Routes**, **Countries**, and so on.
  When the same thing is mentioned in running text, use the English term too
  (_"tetapkan Gate & Berth"_, _"ganti Vessel"_), not _gerbang_, _dermaga_ or _kapal_.
- **Button and status names** — **Set As Boarding**, **CheckedIn**, **Boarded**.
- **Pre-Immigration**, **Boarding** and **read-only** — never _pra-imigrasi_,
  _naik kapal_ or _hanya-baca_.
- The **Terminal Portal** and **Operator Portal** product names.

Previewing Indonesian locally — `npm start` serves **only one locale**, English by
default, so the language dropdown does nothing in dev:

```bash
npm start -- --locale id     # dev server, Indonesian only
npm run build && npm run serve   # both locales, dropdown works
```

After adding or renaming a **sidebar category**, regenerate the JSON so the new
label appears for translation (existing translations are kept):

```bash
npm run write-translations -- --locale id
```

Two categories with the same label (e.g. both **Administrator** sections) need a
unique `"key"` in their `_category_.json`, or this command fails with a
duplicate-translation-key error.

## Deployment (automated)

`.github/workflows/deploy.yml` runs on every push to `main`:

1. `npm ci` + `npm run build`.
2. Pushes the compiled `build/` to the **`gh-pages`** branch using the built-in
   `GITHUB_TOKEN` (same-repo publish — no App token or extra secrets needed).
3. GitHub Pages serves `gh-pages`.

So: **push to `main` → the site republishes.** You can also trigger it manually from
the **Actions** tab.

### Pages setup (for reference)

Settings → Pages → **Deploy from branch → `gh-pages` / root**.

Never commit to `gh-pages` by hand — CI overwrites it on every build.

### If a deploy gets stuck

If a Pages deployment fails with *"try again later"* and a re-run sits queued, an
orphaned Pages build is usually holding the environment. Kick a fresh build with:

```bash
gh api -X POST repos/Sindo-Ferry/ts-documentation/pages/builds
```

### If the URL changes

If you rename this repo or add a custom domain, update `url`, `baseUrl`, and
`projectName` in `docusaurus.config.js`.
