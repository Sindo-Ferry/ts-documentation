# Terminal Portal Documentation

User guides for the Sindo Ferry portals, built with [Docusaurus](https://docusaurus.io/).

- **Source** lives here in the private `terminal-solution` repo, under `documentation/`.
- **Published** (compiled site only) to the public `meiliverani-erline/ts-documentation`
  repo, which serves GitHub Pages at:
  **https://meiliverani-erline.github.io/ts-documentation/**

Keeping the source next to the app means guides get updated in the same PR as the
feature they document.

## Structure

```
documentation/
├── docs/
│   ├── intro.md                     # Overview / landing page (slug: /)
│   ├── terminal-staff/              # Audience: Terminal Portal (localhost:5000)
│   │   ├── _category_.json          #   category label + order
│   │   ├── sign-in.mdx
│   │   ├── generate-departure-trips.mdx
│   │   ├── set-trip-as-boarding.mdx
│   │   └── check-in-ntl-lm-passenger.mdx
│   └── ferry-operator/              # Audience: Operator Portal (localhost:5001)
│       ├── _category_.json
│       ├── sign-in.mdx
│       ├── check-in-passenger.mdx
│       └── edit-remove-passenger.mdx
├── static/img/<audience>/<module>/  # screenshots, one folder per guide
├── docusaurus.config.js             # site config (url/baseUrl, nav, footer)
├── sidebars.js                      # autogenerated sidebar (reads the docs/ tree)
└── build/                           # generated output (gitignored)
```

## Local development

```bash
cd documentation
npm install        # first time only
npm start          # dev server with live reload → http://localhost:3000/ts-documentation/
```

Build + preview the production output:

```bash
npm run build
npm run serve      # serves ./build at http://localhost:3000/ts-documentation/
```

> Requires Node 18+.

## Adding a new guide

1. **Capture screenshots** from the running app and save them under
   `static/img/<audience>/<your-guide-slug>/` (e.g. `01-...png`, `02-...png`).
2. **Create the guide** at `docs/<audience>/<your-guide-slug>.mdx` with frontmatter:
   ```md
   ---
   id: <unique-id>
   title: <Full Title>
   sidebar_label: <Short Sidebar Label>
   sidebar_position: <N>          # order within the audience category
   description: <one-liner>
   ---
   ```
   Reference images with root-absolute paths, e.g.
   `![alt](/img/<audience>/<slug>/01-....png)` — Docusaurus applies the baseUrl and
   fingerprints them automatically.
3. **Link it** from `docs/intro.md` (and cross-link related guides).
4. **Verify:** `npm run build` — the build **fails on broken image paths** and warns on
   broken links. Fix any before pushing.

## Deployment (automated)

A GitHub Actions workflow in the app repo,
`.github/workflows/deploy-docs.yml`, does this on every push to `main` that touches
`documentation/**`:

1. `npm ci` + `npm run build` in `documentation/`.
2. Pushes the compiled `build/` to the `gh-pages` branch of the public
   `meiliverani-erline/ts-documentation` repo (via an SSH deploy key stored as the
   `DOCS_DEPLOY_KEY` secret).
3. GitHub Pages serves that branch.

So: **push to `main` → the site republishes automatically.** You can also trigger it
manually from the repo's **Actions** tab (workflow: *Publish documentation to
ts-documentation*).

### One-time deploy setup (already done, for reference)

- SSH deploy keypair generated; **public** key added to
  `meiliverani-erline/ts-documentation` → Settings → Deploy keys (write access);
  **private** key stored as `DOCS_DEPLOY_KEY` secret in `terminal-solution`.
- `ts-documentation` → Settings → Pages → **Deploy from branch → `gh-pages` / root**.

### If the URL changes

If you rename the Pages repo or add a custom domain, update `url`, `baseUrl`, and
`projectName` in `docusaurus.config.js`, and `external_repository` in the workflow.
