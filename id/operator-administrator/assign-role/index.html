Assign a Role to a User

Assigning a role is how a user actually gets their access. Everything up to this point has been preparation.

Users → ⋯ → Manage Security → Roles tab → Assign / Revoke

Permission needed: operator.security.is_super_admin

Only a Super Admin can change a user’s roles

The buttons in both panels are gated on operator.security.is_super_admin — not on operator.roles.write or operator.users.write.

So an ordinary administrator can open this page and read it, but the action buttons will not appear for them. If you can see the lists but not the buttons, that is why.

catatan

You need the permissions named above. The screenshots below use https://ts-operator.sindoferry.com.sg/.

Before you start​

  • You are signed in to the Operator Portal — see Sign In to the Operator Portal.
  • The user exists and the role exists with its permissions set.
  • You are a Super Admin.

Step 1 — Open the user's security profile​

Open Users, find the user, and use the row's ⋯ menu → Manage Security (route: /users/edit?id=…).

The User Security Profile opens, headed with the user's name, email and any Admin / Super Admin badges. Confirm you have the right person — the email is shown under the username.

Three tabs: Roles, Direct Permissions and Effective Access.

Step 2 — Open the Roles tab​

Two panels:

PanelWhat it holds
Available Roles (left)Roles the user does not hold.
Assigned Roles (right)Roles they do hold. Shown on a tinted background.

Both panels work the same way:

  • Filter box — type to narrow the list. With hundreds of permission strings, this is the only practical way to find one.
  • Tick the rows you want. The checkbox in the header ticks everything currently shown.
  • The action button shows the count — Assign (3) — and stays disabled until at least one row is ticked.
  • Each panel scrolls independently; the selection clears after every action.

Step 3 — Assign a role​

Tick the roles in Available Roles and click Assign (N). They move across immediately.

Step 4 — Revoke a role​

Tick the roles in Assigned Roles and click Revoke (N).

No confirmation, immediate effect

Neither panel asks you to confirm. The change applies at once — including to a user who is mid-shift with the portal open.

Revoking a scanning role from someone working the boarding gate stops them scanning straight away. Time these changes between shifts where you can.

You must also revoke a role from every holder before the role itself can be deleted.

Step 5 — Check the result​

Open the Effective Access tab. It lists every permission the user actually has — the union of all their roles plus any direct permissions.

This is the tab that answers "why can this person do that?" and "why can't they?" Check it after every change rather than assuming the role was enough.

More than one role is fine

Roles add together. Someone who is both Check-in Counter and Boarding Gate Officer gets both sets of permissions. There is no ranking and no conflict — permissions only ever accumulate.

If a change is rejected​

MessageWhat it means
"One or more Role IDs are invalid." / "Invalid Role IDs detected: …"The page's list is stale — a role was deleted or renamed while you had it open. Reload and try again.

Troubleshooting​

SymptomLikely cause
Role assigned, but the user still cannot do the thingThe role has no such permission. Check the role's permissions, then the Effective Access tab.
The user sees nothing after signing inThey have no roles, or their roles are empty.
The user can do everything regardless of rolesThey are an Admin — the flag bypasses all of this.
No Assign / Revoke buttonsYou are not a Super Admin.
Changes do not appear for the userAsk them to sign out and back in.
