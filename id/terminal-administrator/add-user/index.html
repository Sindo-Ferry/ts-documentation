Add a New User

Creating a portal user is one half of giving someone access. The other half is their own registration — and the two are matched by email address.

Users → Create User → username + email → Create User

Permission needed: terminal.users.write

catatan

You need the permissions named above. The screenshots below use https://ts-terminal.sindoferry.com.sg/.

How the two accounts fit together​

Read this before you create anyone

There are two separate things with the same person behind them:

Created byHolds
Sign-in accountThe person, at Register an AccountEmail + password
Portal userYou, hereUsername, roles, permissions, active flag

They are linked by email address, at sign-in time. If the two emails differ by so much as a typo, the person will confirm their email, you will activate their user, and they will still be told their account is not provisioned — with nothing obviously wrong on either side.

Use the exact email address the person registered with.

Before you start​

  • You are signed in to the Terminal Portal — see Sign In to the Terminal Portal.
  • You hold terminal.users.write. Without it the Create User button does not appear.
  • You know the exact email address the person has registered — or will register — with.

Step 1 — Open Users​

In the sidebar, Roles and Users sit under the Security group. Open Security → Users (route: /users).

Each row shows the username with the email beneath it, and status badges: Active / Inactive, plus Admin and Super Admin where they apply.

Step 2 — Click Create User​

Create User is at the top right. The New User form has exactly two fields.

Step 3 — Fill in the two fields​

FieldRules
UsernameAt least 3 characters. Must be unique. This is the display name across the portal and the audit trail.
Email AddressMust be a valid email, and must match the address on their sign-in account. Must be unique.

Then click Create User.

There is no Admin tick on this form

Administrator status is not set at creation — the form is username and email only. To make someone an admin, create them first, then use Grant or Revoke the Admin Role.

Step 4 — What happens next​

On success you see a toast: "User created — a notification email has been sent to [email]."

The person receives a "You've been added to [system name]" email containing a link to the registration page, reminding them to register with that same address if they have not already.

The email is best-effort

The user record is saved first, and the email is queued afterwards. If the mail system is having a bad day, the user is still created — you just will not get the toast's promise honoured. Tell the person directly rather than assuming the email arrived.

Step 5 — Activate them​

A new user cannot sign in yet. Two more things are needed:

  1. They register (or have already registered) with the matching email and confirm it — see Register an Account.
  2. You activate them — see Activate or Deactivate a User.

Then give them access:

  1. Assign a role — otherwise they can sign in and see almost nothing.

If the save is rejected​

MessageWhat it means
"Username is required."The username arrived empty.
"Username is already taken."Another user has it. Usernames are unique.
"Email is required."The email arrived empty.
"Email is already registered."A portal user already exists with that address — search the Users list before creating a second one.
"Invalid email address."The form's own format check.

Troubleshooting: "not provisioned" after everything looks right​

The person signs in and still sees "Login succeeded, but your account is not provisioned for Opusbay access. Please contact your administrator." Work through these in order:

  1. Is the portal user Active? An inactive user gets exactly this message.
  2. Do the emails match exactly? Compare the address on their row here against the one they registered with. This is the most common cause.
  3. Have they confirmed their email? Registration is not complete until they do.
  4. Are they in the right portal? A Terminal Portal user cannot sign in to the Operator Portal, or vice versa — they need a user record in each.
