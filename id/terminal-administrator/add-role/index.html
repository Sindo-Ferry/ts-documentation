Add a New Role

A role is a named bundle of permissions — Boarding Gate Officer, Check-in Counter, Head of Operations. You create the role here, give it permissions, then assign it to people.

Roles → Create Role → name it → Create Role

Roles are the right way to grant access

You can give a person permissions directly, but roles are what you should reach for. One change to a role updates everyone who holds it; direct permissions have to be fixed person by person. See Manage a User's Direct Permissions.

Permission needed: terminal.roles.write

catatan

You need the permissions named above. The screenshots below use https://ts-terminal.sindoferry.com.sg/.

Before you start​

  • You are signed in to the Terminal Portal — see Sign In to the Terminal Portal.
  • You hold terminal.roles.write. Without it the Create Role button does not appear.
  • You know roughly which permissions the role will need — though you assign those in the next step, not here.

Step 1 — Open Roles​

In the sidebar, Roles and Users sit under the Security group. Open Security → Roles (route: /roles).

The list shows one row per role, with a search box and a ⋯ actions menu on each row.

Step 2 — Click Create Role​

Create Role is at the top right. The Add New Role page opens with a single form, headed New Role — "Define the identity of this security role."

Step 3 — Name the role​

FieldRules
Role NameAt least 2 characters. Must be unique. Example placeholder: e.g. Project Manager.

Then click Create Role. You are returned to the Roles list.

Name it after the job, not the person

Boarding Gate Officer ages well; Budi's role does not. The name is what the next administrator reads when deciding who should hold it, and it is also what you must type to delete the role later.

If the save is rejected​

MessageWhat it means
"Role name must be at least 2 characters."The form's own check, before anything is sent.
"Role name is required."The name arrived empty.
"Role name must be unique."A role with that name already exists. Check the list — you may be about to duplicate one that already does the job.

What you have now — and what is missing​

The role exists, but it is empty. A role with no permissions grants nothing, and assigning it to someone changes nothing about what they can do.

Two steps remain:

  1. Give the role its permissions.
  2. Assign the role to a user.
